# Project technical debt

Entries about one library or component are in [debt](debt/), one file per library or component, under the same sections as this page. Entries that belong to none stay here.

### Build

- Building on Windows requires a specific version of mingw - MinGW-w64 GCC 15.2.0 (`winlibs-gcc15`, `x86_64-ucrt-posix-seh`)
- Even compiled prx libraries on Windows require nearby (static linking of these dependencies causes conflicts):
  - libgcc_s_seh-1.dll
  - libstdc++-6.dll
  - libwinpthread-1.dll

### Direct memory

- Windows direct-memory backing reserves a paging-file section and commits each mapped guest page before setting its protection. Committed physical contents remain in the section across unmap/remap and are released when the backing and its remaining views are destroyed; commitment is not recovered merely by unmapping a page. Linux retains its existing backing. Peak gameplay memory and Windows versions other than the tested host remain unverified.

### Functional

- [Cancellation coverage](ARCHITECTURE.md#thread-cancellation) checks deferred request handling and recovery, not full asynchronous support or console ABI compatibility. Cancellation during file/socket I/O, sleep interruption, cancellation versus exit/detach, condition signal conservation under cancellation, and safe rejection of non-null invalid or reclaimed thread handles remain unverified. No console title or homebrew establishes the cleanup NIDs or buffer layout. Accepted asynchronous mode currently has no diagnostic for its deferred behavior.
- `--to-intel` guest module trampolines are covered only by a synthetic relinker test; no game title has been verified with them on Linux or Windows.

- The macOS relinker fixtures use GNU cleanup and TLS-model attributes through standard attribute syntax. C cleanup must exercise `__gcc_personality_v0`, and the initial-exec TLS access must retain that relocation model; replacing these with C++ RAII or default TLS would change the behavior under test.

- The optional native ARM64 graphics target is qualified only for the pinned source-built `gpu_cube` variant documented in [BUILD](BUILD.md#source-built-native-arm64-graphics-fixture). Its explicit pointer/layout and provider-effect contracts are tied to the reconstructed ELF hash. Mapping guards check readability, not object identity, bounds, ownership or asynchronous lifetime. Native graphics does not provide a complete game runtime, x86 exception restoration, x87/variadic formatting or arbitrary module loading. The Apple write-changed path uses byte-selective native stores where x86 uses SSE masks. No game compatibility or speedup is established.

- The checked graphics AOT profile is under qualification. Native mapping guards do not prove object type, ownership, lifetime, asynchronous stability or relocation of arbitrary guest integer addresses. Output/layout assertions need matched source evidence; internal bounded outputs and frame exclusions are enforced natively. Full current-base graphics execution and multi-frame comparison are still required before compatibility claims.

- The [native ARM64 AOT compiler](../../core/aot/compiler.py) is experimental. Function/ABI contracts and indirect-call target sets are supplied with input hashes; their completeness is not inferred or proved. It supports a bounded scalar, SSE and VEX subset and rejects unsupported operations. Acyclic direct-call memory effects are inferred from validated code for private frame and fixed image writes. Provider memory effects are caller-verified annotations, not automatically inferred or bound to the linked binary. Their correctness, absence of guest reentry and external entry-point binding preconditions remain the integrator's responsibility. Unqualified imports, indirect calls, recursive call chains, unresolved parameter writes and unproved indexed aliases still invalidate pointer-cell proofs. Indexed frame writes have bounded proofs only for single-entry straight-line loops with constant initialization, one positive 64-bit increment and an exactly reachable equality exit before the increment. Calls, extra entries/exits, wrapping counters and dynamic bounds are excluded; these proofs do not reconstruct pointer cells. Fixed-size parameter-relative writes are inferred only for proven pointer origins with constant offsets and propagated through acyclic direct/tail calls. Dynamic extents, indexed parameter writes and unresolved aliases remain conservative. Exact stack pointer cells retain provenance through full-width spills/reloads and equal-origin control-flow joins, including declared incoming stack arguments. General range analysis, nonconstant effect sizes and arbitrary struct-pointer reconstruction remain unimplemented. Scalar stack-byte constants support native null arguments and known effect sizes; these constants do not establish native pointer provenance. Explicit checked stack accesses emit native bounds/alignment guards; object layouts still require recovery evidence, invalid accesses trap rather than deliver guest faults, and instrumentation costs are not game-performance qualified. Arbitrary pointer reconstruction, x87, guest fault delivery, guest TLS, C++ exceptions, aggregates, varargs, atomics, concurrent memory ordering, module closure and lifecycle remain incomplete. Its emitted objects need native import providers. The optional native image registry validates process metadata and allocator callback bindings for one main image; module unloading, dynamic metadata replacement and allocator extension callback ABIs are not supported. The optional immutable-data profile uses native symbolic relocations and startup page-protection checks; guest/provider writes, remapping and rebinding of those regions are outside its contract. The optional source-built hello_notify runtime provides one statically linked main image and its required native providers; it does not provide a complete game runtime or application package. The current macOS guest heap uses the existing host-allocation path rather than a reserved PS5 address arena. Main-image allocation registration reads actual Mach VM page protections; dynamic module registration is not implemented. Linux x86-64 validates and cross-compiles the example without execution. The optional Linux ARM64 validation target emits ELF and executes the source-built example natively; it uses the same lowering and native providers with ELF RELRO instead of Mach-O readonly sections. This validates the tested program path, not all guest instructions or Linux ABI combinations; no full Linux ARM64 game port is provided. The example annotation builder accepts only its pinned sources, known ABI declarations, matched object code and fixed DWARF stack location; it is not general automatic ABI recovery.

- Native AOT integer and SIMD semantics follow [Intel SDM Volume 2](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html), with [x86-64 SysV ABI](https://gitlab.com/x86-psABIs/x86-64-ABI) to [Apple ARM64 ABI](https://developer.apple.com/documentation/xcode/writing-arm64-code-for-apple-platforms) reconstruction. The floating-point profile requires nearest-even rounding, preserved subnormals, masked exceptions and unobserved status flags/NaN payloads; FPCR is checked at entry. Division and aligned-access violations trap instead of reproducing guest exception delivery. Native tests and Rosetta SSE references do not qualify PS5 hardware behavior; AVX2 has independent integer-oracle tests but no x86 AVX2 execution oracle.

- [sceKernelGetModuleInfoForUnwind](../../core/libs/prx/libkernel/Module/src/Module.cpp) (libkernel) - on Linux the tables come from `sceKernelGetModuleInfoFromAddr`, whose `eh_frame_size` includes the zero terminator, as measured on firmware 13.60 (reported in [#2419](https://github.com/boykopovar/AnyPS5/issues/2419), not reproduced here); on Windows it is assumed to stop before the terminator. LLVM libunwind's `CFI_Parser::findFDE` stops at the terminator or the length, whichever comes first, so it finds the same FDEs either way. Only the main executable and `.guest.prx` images report tables; other host images report none, as on Windows; on macOS the tables come from the `eh_frame_hdr` of a guest image and `eh_frame_size` stops before the terminator, and a host image reports none

- [sceKernelGetModuleInfoFromAddr](../../core/libs/prx/libkernel/Module/src/ModuleInfo.cpp) (libkernel) - the 0x1A8-byte info layout follows the [shadPS4](https://github.com/shadps4-emu/shadPS4) reimplementation; a title's `libc.prx` reads only `id` (PPSA14632). The meaning of `flags` is unknown; only 2 is accepted. The input `st_size` is ignored, because PPSA21703's `libc.prx` passes an uninitialized 0x1A8-byte buffer; the full size is written back. The id is the `sceKernelLoadStartModule` handle of an image opened through the loader and otherwise a stable id from the same range. The name is the host file name without `.guest.prx`. An image with more than 4 load segments (the converted executable has 7) reports its first 4. `tls_offset` is 0 and `ref_count` is 1, as the host loader exposes neither. On Windows the module is the PE image holding the address: a relinked image reports its `.elf` sections as segments and the eh_frame_hdr recorded in `.ehmeta`, any other image its first 4 sections with memory access and the `.ehfram` section without an eh_frame_hdr; the TLS fields and `init_proc_addr`/`fini_proc_addr` are 0 Not implemented on macOS, nor are `sceKernelGetModuleList` and `sceKernelGetModuleInfo`.

- On macOS (MoltenVK on an Apple GPU), 16 AGC tests fail on hardware limits:

  - Metal has no 64-bit floats (the 7 agc_driver_f64_* tests and agc_driver_division_result_modifiers);

  - it has no 64-bit atomics (agc_driver_buffer_atomics*, agc_driver_global_atomics64, agc_driver_global_atomics_float, agc_driver_global_atomics_lanes);

  - MoltenVK offers no VK_KHR_shader_clock (agc_driver_shader_clock).

- agc_driver_sdwa_float_selectors fails on macOS: an f16 multiply that should give -0.0 gives +0.0. In isolation, Metal keeps the sign through each step of the same chain (half to float, multiply, the software float-to-half conversion). The cause, found on an M1 Pro: SPIRV-Cross's MSL backend computes a precise multiplication as `fma(l, r, 0)`, which turns a -0.0 product into +0.0. A fix is submitted as KhronosGroup/SPIRV-Cross#2704; it reaches this project when MoltenVK takes that SPIRV-Cross.

- The [SPIR-V backend](../../core/shader/recompiler/SpirvBackend) works around SPIRV-Cross, which MoltenVK uses to make Metal shaders:

  - ordered not-equal is emitted as an unordered not-equal and two NaN tests on the bits, because SPIRV-Cross writes OpFOrdNotEqual as `!=`;

  - NaN tests read the bits;

  - an image atomic comes after an image-memory barrier, because Metal shows an invocation's earlier image stores to its atomics only after a texture fence;

  - subgroup results pass through a Private variable, so that SPIRV-Cross does not move them into `?:`, `&&` or `||`, where only some lanes would run them.

- On macOS every guest image keeps its own TLS block and thread pointer ([MacOsImage.cpp](../../core/relinker/elfpatcher/src/macos/MacOsImage.cpp)). Another module can reach a module's exported TLS variable only through general-dynamic access (DTPMOD64/DTPOFF64). The image initializer fills those slots from the TLS index the defining module exports. As on Windows, initial-exec access (TPOFF64) to another module's TLS fails the relink, and so do TLS relocations in the executable.

- [Vertex lane bounds](../../core/shader/recompiler/Optimization/src/ConstantFolder.cpp) fold `LaneId < N` for `N >= 32` only in wave64 vertex programs on a 32-lane host. This follows the existing one-guest-lane-per-invocation vertex lowering and the [Vulkan SubgroupLocalInvocationId range](https://registry.khronos.org/vulkan/specs/latest/man/html/SubgroupLocalInvocationId.html). Compute/mesh paired lanes, wave32, unknown host width and partial masks retain their comparisons. The cube regression was exercised on Apple M5 Max with MoltenVK; console equivalence of the surrounding NGG lowering remains unverified.

- The [native graphics closure](../../core/libs/native/CMakeLists.txt) excludes `Math.cpp`, which now asserts x87 long-double storage for `__signbitl`. Apple ARM64 long double is binary64; weakening that assertion would accept a different guest ABI. The other math providers in that translation unit are also unavailable in this optional closure until the x87 providers are separated. Requiring an excluded provider fails at link time; the qualified cube does not use them.

- [Guard recipes](../../core/aot/contract_recipe.py) derive mapping-check sites only under explicitly qualified native-address and ABI policies. Source identities and fact digests detect stale evidence; they do not prove declarations correct. The cube recipe preserves its existing one-byte mapping checks and nullable pointer arguments. Object identity, full access bounds and lifetime remain source obligations. The independent recipe tests cover synthetic load/call inputs, not an unseen full program or general ABI recovery.

- The AOT provider catalog qualifies source-level identities and reviewed declarations, not arbitrary linked provider binaries. Changes to source, dependencies or facts require requalification. The caller remains responsible for the final linked implementation and per-call preconditions. The initial Apple catalog uses the provider notification size_t ABI and does not qualify the loader initialization profile for other consumers. Guest caller register bits must satisfy the selected provider ABI; source prototypes alone do not establish this. DWARF candidate recovery is limited to matching source-built C objects, scalar ABIs, a verified fixed RBP prologue and nonoverlapping fixed-location scalar/array locals. It is not stripped-binary ABI inference. Semantics follow DWARF 4 sections 2.5, 3.3, 4.1 and 5; compiler flags, source provenance and pointer lifetime remain separate obligations.

- The native `pad_input` consumer uses the original source with an explicit SysV O0 debug profile. It recovers four scalar function signatures and 26 nonoverlapping frame objects from matching DWARF; it still declares the native-pointer lifetime policy, CRT lifecycle and nontrapping constant-10 division profile. Ten imports resolve through the provider catalog, but seven entries were first qualified for this consumer and must not be counted as previously recovered knowledge. The initialization bridge remains a consumer obligation. Test-only provider adapters simulate input and failure paths; they do not establish physical-controller behavior, shared-provider completeness or PS5 compatibility. No performance advantage is claimed for this O0 input.
- The independent notification transfer probe uses unchanged `ps5-payload-dev/sdk` source with a qualified alternative compilation/CRT profile. It does not validate that project's loader or distribution. Its old-style `main()` requires an explicit source ABI; generic recovery retains the unresolved obligation. `pad_input` does not create a video output or validate a physical-controller event pump: production-provider smoke covers the state API and timer, while interaction coverage uses test-published state.

The incremental native-AOT DWARF dossier supports matching C DWARF 4 companions and fixed RBP frames only. Location lists follow DWARF 4 sections 2.6.2 and 2.17; lexical and inline scopes constrain their PC ranges. Register/value expressions, overlapping storage and missing/optimized-away variables remain qualification obligations. No optimized source signature or location expression is automatically promoted to a machine ABI or object-lifetime proof. CFA expressions, split storage, general stripped recovery and optimized internal calling-convention reconstruction remain unsupported.

Native AOT finite dispatch recognizes a RIP-relative LEA followed within a straight-line region by an eight-byte indexed memory CALL/JMP. The table must be in an explicitly qualified immutable segment and consist of contiguous relative relocations. Calls require internal targets with compatible qualified machine ABIs; jumps require instruction boundaries inside the same function. Native readonly page validation, pre-load bounds/alignment checks and pre-dispatch membership checks enforce the table assumptions. Known alias writes reject; arbitrary register dispatch, relative 32-bit jump tables, mutable tables and inferred target ABIs remain unsupported. Declared callback targets now also have runtime membership checks. Immediate ROL/ROR follow Intel SDM Volume 2 RCL/RCR/ROL/ROR, including count masks, partial-register results and undefined OF for masked counts other than one; variable counts remain unsupported.

The optimized public SHA-256 component additionally exercises BSWAP and SSE2 byte addition, unsigned byte maximum, byte/dword equality, low byte/word interleaving, arithmetic dword shifts and MOVMSKPS. Their lowering follows the corresponding Intel SDM Volume 2 instruction definitions; integer lane probes compare against x86 execution under Rosetta. This is instruction coverage for qualified inputs, not automatic SIMD reconstruction or a speedup claim.

The optimized controller and external component profiles still require reviewed C source, matching DWARF companions, qualified machine ABIs and valid C object lifetime/bounds. Only fixed debug storage is consumed; register/value location expressions, optimized-away variables and scoped overlaps remain explicit dossier obligations. The compiler checks frame/control-flow state separately, rather than widening those location ranges. The symbol-free input does not recover function ABIs without its companion. The SHA-256 input is a component harness and does not qualify the application's loader or updater. The musl holdout is a small independent component, not evidence of general stripped-binary conversion. Host memset/memcpy/strlen bindings are qualified only for their reviewed direct-delegation wrappers and LP64 ABI; memcpy nonoverlap and valid string/buffer extents remain call preconditions. Physical controller input and general optimized internal ABI reconstruction remain open.

Native AOT register transport preserves defined-bit masks across GPR MOV and scalar LEA. Optimized code may copy a partly defined register and observe only a defined byte; copying does not make its other bits defined. Scalar addition in LEA retains only the common defined low-bit prefix. Observable uses (memory addresses/stores, conditions, call arguments and returns) retain their validity checks, and native lowering still rejects unresolved machine-state values. The regression comes from the Clang 17 O2 controller decimal-formatting loop.

Native AOT bundles currently require a closed acyclic DT_NEEDED graph, strong unambiguous exports and qualified scalar ABIs/data extents. Default-visible ELF interposition, GNU symbol versioning, external data addends, arbitrary dlopen/hot unload, TLS and initializer arrays remain unsupported. SCE identity normalization supports the existing PS5 import tags and module/library export metadata variants; missing or ambiguous identities reject. Only complete PT_LOAD ranges covered by PT_GNU_RELRO become immutable automatically; readonly validation is still performed on the native image. The bundle registry is separate from DynamicLoader's runtime file-loading interface and does not claim drop-in compatibility with all module APIs.
