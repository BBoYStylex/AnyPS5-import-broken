# libSceUsbStorage technical debt

### Unknown function info

- [sceUsbStorageGetDeviceInfo](../../../core/libs/prx/libSceUsbStorage/Export.cpp) (libSceUsbStorage) - the 824-byte report follows [SharpProspero's bindings](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Platform/UsbStorage.cs), which recovered the layout from the service module's `sceUsbStorageGetDeviceInfo`: the volume size at 0x000, the vendor at 0x016, the product at 0x120, the serial at 0x228 and the flags at 0x330, each name in a 256-byte field. The flags are written as 0, as the value the service masks with 0xd0 is not published, and the reserved fields are 0
- [sceUsbStorageGetDeviceList, sceUsbStorageGetMountPointOfShellCore, sceUsbStorageIsExist and sceUsbStorageRequestMap](../../../core/libs/prx/libSceUsbStorage/Export.cpp) (libSceUsbStorage) - the device ids are the ones the host assigns in enumeration order, not the console's, and the mount point is the path the host's system mounted the device at, not a path the service creates. The service reports at most eight devices, as [SharpProspero's bindings](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Platform/UsbStorage.cs) state the service does
- [sceUsbStorageRegisterCallback, sceUsbStorageUnregisterCallback and the four map callbacks](../../../core/libs/prx/libSceUsbStorage/Export.cpp) (libSceUsbStorage) - the callback takes the 16-byte parameter that [SharpProspero's bindings](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Platform/UsbStorage.cs) recovered from the service module's dispatchers: the event, the device id and the flags, followed by the user data. The events are delivered when the guest next calls the service, so a title that never calls it again is not told about a device that arrived or left
- [sceUsbStorageGetdentsOpen, sceUsbStorageGetdentsRead and sceUsbStorageGetdentsClose](../../../core/libs/prx/libSceUsbStorage/Export.cpp) (libSceUsbStorage) - the entries use the guest directory entry layout that `sceKernelGetdirentries` writes, and the handle is a USB storage service handle rather than a guest file descriptor, so it cannot be used with the other file calls

### Functional

- [libSceUsbStorage](../../../core/libs/prx/libSceUsbStorage/Export.cpp) finds the USB mass storage devices of a Linux host: the block devices whose device path is a USB one. The vendor, product and serial come from the USB device directory, the volume size from the block device's sector count and the mount point from the host's mount table. Only Linux is inspected; the other hosts find no device
- [sceUsbStorageRequestUnmap](../../../core/libs/prx/libSceUsbStorage/Export.cpp) (libSceUsbStorage) - the host's mounts belong to its system, so a device cannot be unmapped through this service and the call throws. [SharpProspero's bindings](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Platform/UsbStorage.cs) report the service's own errors, which are not used for a call the host cannot make
- [sceUsbStorageRequestMap](../../../core/libs/prx/libSceUsbStorage/Export.cpp) (libSceUsbStorage) - the requested directory and the volume size hint are ignored, as the host's system mounts the device itself; the call reports the mount point the device has and a mount id derived from the device id
