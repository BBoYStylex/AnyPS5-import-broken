# libSceSsl technical debt

### Unknown function info

- [sceSslCreateConnection, sceSslDeleteConnection, sceSslSetVerifyCallback, sceSslConnect, sceSslRead, sceSslWrite, sceSslClose](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - imported by `ffmpeg.prx`, PPSA01317 and PPSA07411. Signatures follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/Net/Http.cs#L195-L252), which also says the socket stays open after `sceSslDeleteConnection`. `sceSslConnect` runs a Mbed TLS 3.6.7 client handshake over the native socket behind the title's libSceNet descriptor (found through the kernel's socket lookup, so the socket is only checked at connect time and an unknown descriptor throws), with the context's loaded CAs as the trust store, its client certificate and key when loaded, the hostname as SNI, TLS 1.2 as the minimum for every `sceSslSetMinSslVersion` value (the library has no TLS 1.0/1.1), TLS 1.3 allowed, and the `sceSslSetAlpn` string split on commas; whether the console expects a comma-separated list or the TLS wire format is unknown. Verification runs after the handshake against the enabled options: with `SERVER_VERIFY` (0x1) off nothing is checked; with it on, an untrusted chain fails with `SSL_ERROR_UNKNOWN_CA` (0x8095F00C) only when `KNOWN_CA_CHECK` (0x20) is on, a name mismatch with `SSL_ERROR_CN_CHECK` (0x8095F00B) only when `CN_CHECK` (0x4) is on, dates with `SSL_ERROR_NOT_AFTER_CHECK`/`SSL_ERROR_NOT_BEFORE_CHECK` (0x8095F00D/E) only when their checks (0x8/0x10) are on, and any other certificate problem with `SSL_ERROR_INVALID_CERT` (0x8095F00A). The initial options are still taken as 0, so a title that enables nothing gets no verification. When a verify callback is set it is called once after the handshake with the connection id, that code (0 when the chain passed), handles to a copy of the peer chain usable with `sceSslGetSubjectName` and friends until the connection is deleted, the chain length and the user argument; a negative return fails the connect with `SSL_ERROR_APPLICATION_VERIFICATION_CALLBACK_CHECK` (0x8095F0FD) and any other return accepts the connection whatever the code was, following SharpProspero's "a negative return fails the handshake". The callback runs with the connection's I/O lock held, so it must not use the same connection. A failed verification closes the session with a close notify: later `sceSslConnect` calls return the same code, and `sceSslRead`/`sceSslWrite` throw. On a non-blocking socket connect, read and write return `SSL_ERROR_WANT_POLLIN`/`SSL_ERROR_WANT_POLLOUT` (0x8095F013/14) and the title retries after polling the socket; a receive timeout returns `SSL_ERROR_READ_TIMEOUT` (0x80951710), a peer close notify `SSL_ERROR_EOF` (0x8095177C), a transport closed without one or reset `SSL_ERROR_SOCKET_CLOSED` (0x8095170D), a fatal alert `SSL_ERROR_FATAL_ALERT` (0x8095F010), an exhausted memory pool `SSL_ERROR_OUT_OF_MEMORY` (0x809517D5) and any other Mbed TLS failure `SSL_ERROR_INTERNAL` (0x8095F009); the codes and their values follow [KytyPS5's errno.h](https://github.com/KytyPS5/KytyPS5/blob/4865dd92ca6b6bb907748f125883093af038f53b/src/libs/errno.h), and which of them the console returns in each case has not been measured. `sceSslRead` and `sceSslWrite` ignore `flags`, return the byte count, and throw before the handshake has completed or after `sceSslClose`; `sceSslClose` sends the close notify once and leaves the socket to the title. All TLS state is allocated from the context's pool, so a pool too small for the handshake buffers (about 40 KiB plus the peer chain) fails the connect with `SSL_ERROR_OUT_OF_MEMORY`; the pool size a title needs on the console is unknown. `sceSslTerm` tears down the open transports of its connections before the context goes away. An unknown context returns `SSL_ERROR_INVALID_ID` (0x8095F006), as `sceSslGetMemoryPoolStats` does on the console and as [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/4865dd92ca6b6bb907748f125883093af038f53b/src/libs/network.cpp#L2688-L2720) and [sharpemu](https://github.com/sharpemu/sharpemu/blob/29021b5a71bbc80f262d887e6ba18b3a72963f49/src/SharpEmu.Libs/Network/SslExports.cs#L41-L54) return for other context calls; for an unknown connection, a connection whose context was terminated and a null host the console's codes are unknown, so these throw. `sceSslSetVerifyCallback` accepts any callback, null included, and returns 0; none of this is verified on the console. `SSL_ERROR_BEFORE_INIT` (0x8095F001) is never returned, as the library keeps no state apart from its contexts
- [sceSslGetSerialNumber, sceSslGetSubjectName, sceSslGetIssuerName, sceSslGetNameEntryCount, sceSslGetNameEntryInfo, sceSslFreeSslCertName](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - signatures and context ownership follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Interop/Net/Http.cs#L293-L350). Operations take a context handle as their first argument and operate on certificate and name handles scoped to that context. `sceSslGetSerialNumber` copies into a caller-allocated output buffer or queries the required length when the buffer is null or capacity is zero; a buffer smaller than the serial number returns `SSL_ERROR_INVALID_ARG` (0x8095177a). Mbed TLS parses the certificate's serial number and X.509 subject and issuer distinguished names, extracting OID attribute short names (or numeric strings) and value strings. An unknown context, unknown or expired certificate handle or invalid certificate name handle throws; null output pointers or out-of-range entry indices return `SSL_ERROR_INVALID_ARG` (0x8095177a). The error codes, the zero-capacity length query, the NUL-terminated truncation of name entry strings with the full value length in `valueLen`, and the lifetime of name handles (released only by `sceSslFreeSslCertName` or when the context is terminated) have not been measured on a PS5
- [sceSslLoadCert, sceSslGetCaList, sceSslFreeCaList, sceSslGetCaCerts, sceSslFreeCaCerts, sceSslUnloadCert](../../../core/libs/prx/libSceSsl/Export.cpp) (libSceSsl) - signatures and layouts follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Net/Http.cs). PPSA15508/01.002.000 calls `sceSslLoadCert` with one 1,408-byte PEM CA and null client certificate/key arguments; this confirms that call shape, not console error behavior. Mbed TLS 3.6.7 parses DER/PEM chains and checks an optional client certificate/key pair. Imports are retained per context and committed together; a failed import preserves existing credentials. CA queries return independently owned snapshots; unload clears active credentials while outstanding snapshots remain valid. Appending repeated CA imports, snapshot lifetime across unload, memory overhead and error precedence have not been measured on a PS5. Invalid loads, malformed material, exhausted pools and unsupported keys throw rather than inventing console error codes. No root bundle is shipped; an empty context still returns `NOT_FOUND`. The existing null-list error, unknown-context behavior and legacy clearing of foreign raw CA lists remain unchanged. Certificate reader queries reflect active certificates or outstanding snapshots. Loading credentials neither starts a TLS connection nor authenticates a peer
