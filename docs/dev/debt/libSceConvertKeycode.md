### Unknown function info

- [sceConvertKeycodeGetCharacter](../../../core/libs/prx/libSceConvertKeycode/Export.cpp) (libSceConvertKeycode) - `(uint16 keycode, uint32 status, int32 layout, uint32* character)`, with the USB modifier byte at bits 8-15 and the lock keys (num, caps, scroll) at bits 16-18 of `status`, and layout 4 as English (US), follow [SharpProspero](https://github.com/SvenGDK/SharpProspero/blob/60977b29103452b9681ae10c7a9011d44965bf16/src/SharpProspero/Input/KeycodeConverter.cs). Only English (US) is converted; other layouts throw, including 0, which `sceConvertKeycodeGetImeKeyboardType` reports. Keys are USB HID usages converted with the 101-key table of [sceKeyboardGetKey2Char](../../../core/libs/prx/libSceKeyboard/include/KeyCharacters.hpp), so both libraries give the same character: shift and caps lock select capitals, num lock selects the keypad digits, control, alt and GUI do not change the character, Enter, Backspace and Tab give `\n`, `\b` and `\t`, and a key without a character, Escape and Delete among them, gives 0 and success. Whether the console's two libraries agree, and the error for a null character pointer, are unverified. PPSA34063 imports it (#4275)
