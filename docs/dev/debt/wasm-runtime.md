# wasm-runtime technical debt

### Functional

- [AudioOut2 and AudioOut2Lo](../../../core/wasm-runtime/CMakeLists.txt) (WebAssembly) - the SDL-backed AudioOut2 service and its low-latency forwarding exports are not built; titles importing them stop at startup with missing NIDs
- [Guest thread frame chain](../../../core/wasm-runtime/src/Thread.cpp) (WebAssembly) - a guest thread starts with rbp 0, not at the {saved rbp 0, return address 0} record native threads start on, so a frame-pointer walk that stops at a zero return address reads guest address 8 past its last frame instead
- [WebGPU blend constants](../../../core/wasm-runtime/gpu/WebGpuBackend.cpp) (WebAssembly) - WebGPU has one blend constant factor, which takes the constant's RGB for color and its alpha for alpha. A color blend that uses the constant alpha gets the alpha in all four channels; one that uses both the constant color and the constant alpha throws unless the constant's RGB equal its alpha
- [WebGPU compute dispatches](../../../core/wasm-runtime/gpu/WebGpuBackend.cpp) (WebAssembly) - the queue waits for each dispatch to finish, then copies every buffer the program can write back to guest memory, only the bytes that changed. A CPU write to such a buffer while the dispatch runs survives unless the program wrote the same bytes. Programs that write more than 64 MiB of one buffer throw. Images a program writes stay on the GPU like render targets: later draws and dispatches sample them, but guest memory never receives them
- [WebGPU CPU flips](../../../core/wasm-runtime/gpu/Executor.cpp) (WebAssembly) - every CPU flip waits for the graphics-queue submissions ahead of it, as `APS5_CPU_FLIP_IN_ORDER=1` makes the native driver do: a flip from a thread that has never submitted graphics-queue work is not presented ahead of them
- [WebGPU depth targets](../../../core/wasm-runtime/gpu/WebGpuBackend.cpp) (WebAssembly) - CPU writes after first use are ignored and the CPU never reads the GPU depth. First use clears to `DB_DEPTH_CLEAR`; a wholly cleared HTILE plane forces another clear. Noncomparison sampling copies depth to 32-bit float for each draw; stencil sampling throws. Depth comparisons require a depth target and reject bias, derivatives, LOD other than 0 and gathers. Layered comparisons require every layer to have been a depth target. D16 with stencil uses 24-bit depth with stencil and scales constant depth bias by 256
- [WebGPU draws without targets](../../../core/wasm-runtime/gpu/WebGpuBackend.cpp) (WebAssembly) - a draw with neither a color nor a depth target is compiled and then skipped: WebGPU needs an attachment, and the WGSL backend refuses vertex and pixel programs that write memory, so such a draw changes nothing. Occlusion queries are not counted
- [WebGPU storage image count](../../../core/wasm-runtime/gpu/WebGpuBackend.cpp) (WebAssembly) - a compute program writing more storage images than the device's `maxStorageTexturesPerShaderStage` (4 on Chrome with an Intel UHD GPU) writes the smallest extra ones to storage buffers instead, copied from the image before each dispatch and back after it. 16-bit float texels are rounded toward zero, as Intel's image stores do; other GPUs may round them to nearest. A program that also uses more storage buffers than the device has, or whose image is larger than its storage buffer binding size, throws
- [WebGPU texture uploads](../../../core/wasm-runtime/gpu/WebGpuBackend.cpp) (WebAssembly) - every draw hashes the whole guest surface of each texture it samples to tell whether to upload it again. A texture at the address of a render target or a written storage image samples that GPU image only when its size, layer count and texel format match the image's latest use (8-bit RGBA and BGRA count as one format); otherwise the address is taken to hold other data now, as when a title reuses the memory of a released render texture, and the texture is read from guest memory. Cubes are uploaded and sampled as 2D arrays of their faces, like the native driver's views, so filtering never crosses a face edge. Multisampled textures, 3D textures the GPU draws or writes, and storage images with mips throw
- [WebGPU vertex formats](../../../core/wasm-runtime/gpu/WebGpuBackend.cpp) (WebAssembly) - a vertex stream whose format WebGPU lacks (three 8- or 16-bit components, scaled formats) is converted on the CPU to 32-bit components for each draw, with missing components 0 and w 1. Strides that are not a multiple of 4 and instanced vertex fetch throw
