# libSceNpEntitlementAccess technical debt

### Silent stubs

- [sceNpEntitlementAccessRequestConsumeEntitlement, sceNpEntitlementAccessRequestConsumableEntitlementInfo, sceNpEntitlementAccessPollConsumableEntitlementInfo](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - implement only the signed-out path, as there is no PSN sign-in: like the other entitlement requests and polls here, they return `SCE_NP_ERROR_SIGNED_OUT` (`0x80550006`) for any arguments and write no request id, result or info. Whether a signed-out console fails at the request or creates a request whose poll fails is unverified; [idlesauce's PS4 notes](https://github.com/idlesauce/ps4-eboot-dlc-patcher/blob/d1d1e0f0dbd5e06da45b7d8f8ca1827d34546692/prx_src/libSceNpEntitlementAccess.c#L256-L289) say that `sceNpEntitlementAccessRequestConsumeUnifiedEntitlement` "returns ok even offline" and that `sceNpEntitlementAccessPollConsumeEntitlement` reports `0x817D0019`

### Unknown function info

- [sceNpEntitlementAccessGetAddcontEntitlementInfoIndividual](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) (libSceNpEntitlementAccess) - its name and NID are in the [PS5 3.20 export inventory](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceNpEntitlementAccess.c), but no credible prototype was found. It is declared without parameters solely to resolve known imports; this is not an ABI claim
- [sceNpEntitlementAccessRequestConsumeEntitlement, sceNpEntitlementAccessRequestConsumableEntitlementInfo, sceNpEntitlementAccessPollConsumableEntitlementInfo](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - the parameter lists are unconfirmed: they follow [dlc_emu](https://github.com/drakmor/dlc_emu/blob/fcf69b16d46a9850578bce19dc2c1b4dc867cbb5/src/dlc_modules/scenpentitlementaccess_exports.cpp#L146-L220), a replacement module using the SDK header's types, while [idlesauce](https://github.com/idlesauce/ps4-eboot-dlc-patcher/blob/d1d1e0f0dbd5e06da45b7d8f8ca1827d34546692/prx_src/libSceNpEntitlementAccess.c#L185-L254) marks its lists as assumed and has a service entitlement label in the consume request and an `int32_t*` use limit as the poll's third argument, so those two are untyped pointers. A null request id is not checked, though both return their parameter error for it (`0x817D0002` in idlesauce): its order against the signed-out failure is unknown
- [sceNpEntitlementAccessGetEntitlementKey](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - the three-argument signature, 16-byte key and errors `0x817D0002`/`0x817D0007` follow [KytyPS5](https://github.com/KytyPS5/KytyPS5/blob/main/src/libs/libNet.cpp); PPSA01521 passes a service label, entitlement label and output pointer. Only the no-key path is implemented: local entitlement labels carry no keys, and the output is untouched on failure. Console error precedence and key provisioning are unverified
- [sceNpEntitlementAccess{Request,Poll}{Unified,Service}EntitlementInfo{,List}](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) - signatures unknown; no reference implements them, so they are declared without parameters. The single-item variants copy the behaviour of the list ones, with no source of their own. Like the consume requests in the same library, they report the signed-out NP state with `SCE_NP_ERROR_SIGNED_OUT` (`0x80550006`) and write nothing. PPSA15657 calls the unified request during start-up and continues past the error. Whether the console fails at the request or at the poll when signed out is unverified

### Functional

- [sceNpEntitlementAccessGetGameTrialsFlag, sceNpEntitlementAccessGetPftFlag](../../../core/libs/prx/libSceNpEntitlementAccess/Export.cpp) (libSceNpEntitlementAccess) - reports a full game, not a game trial or Play First Trial: writes 0 to the `uint32_t` output and returns 0, and a null pointer returns `0x817D0002`. The single-pointer signature, the value, the one-word write and the error of `sceNpEntitlementAccessGetGameTrialsFlag` follow [sharpemu](https://github.com/sharpemu/sharpemu/blob/a2983692930564815a77f81e74c151268f5b935f/src/SharpEmu.Libs/Np/NpEntitlementAccessExports.cs#L98-L116), which has no `sceNpEntitlementAccessGetPftFlag`; those of `sceNpEntitlementAccessGetPftFlag` follow [dlc_emu](https://github.com/drakmor/dlc_emu/blob/main/src/dlc_modules/dlc_content.cpp), which takes the same `SceNpEntitlementAccessGameTrialsFlag*` as the trials flag, writes the OFF value 0 and returns the parameter error for null; `0x817D0002` is the parameter error of KytyPS5, prosper and `sceNpEntitlementAccessGetEntitlementKey`, while `sceNpEntitlementAccessGetSkuFlag` here returns `0x80558003`. None of this is a console measurement, and PRAGMATA (PPSA02530) shows four live registers at the call, so further arguments are not ruled out
