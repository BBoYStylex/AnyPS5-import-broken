# libSceIpmi technical debt

### Unknown function info

- [libSceIpmi pending exports](../../../core/libs/prx/libSceIpmi/Export.cpp) - 94 named callable exports are listed in the [PS5 3.20 export table](https://github.com/DNNDHH/PS5-3.20_Libs/blob/b2a77c09cd71c01f34c790cfbe98c751a13262ad/libSceIpmi.c) and in the public [ps5-payload-dev SDK](https://github.com/ps5-payload-dev/sdk)'s `sce_stubs/libSceIpmi.c` table, which declares them as functions; the first five were cross-checked against the same module in PS5 firmware 13.60. Their signatures and behaviour are unverified; the declarations use the no-parameter unknown-signature convention and throw through `NotImplemented_nid_no_patch`. The 89 class methods of the SDK's `IPMI::impl::ClientImpl` are declared under their mangled names, with the `_nid_postfix` suffix the project uses for a name that cannot be a plain identifier, so the NID the guest imports is the one the SDK's table gives. An IPMI client is not implemented here: a title that calls one of these gets the throw
- [_ZTVN4IPMI6Server12EventHandlerE](../../../core/libs/prx/libSceIpmi/Export.cpp) - the SDK's table lists the vtable of `IPMI::Server::EventHandler` without a `.type` marker, so it settles neither that the export is an object nor its size, and no other source gives either. It is not exported: a consumer that read the address of a too-small object would read past it. A title that imports it still fails to load
