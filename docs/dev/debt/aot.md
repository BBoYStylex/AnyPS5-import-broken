# aot technical debt

### Functional

- The [native ARM64 AOT compiler](../../../core/aot/compiler.py) is experimental. Function/ABI contracts and indirect-call target sets are supplied with input hashes; their completeness is not inferred or proved. It supports a bounded scalar, SSE and VEX subset and rejects unsupported operations. Acyclic direct-call memory effects are inferred from validated code for private frame and fixed image writes. Provider memory effects are caller-verified annotations, not automatically inferred or bound to the linked binary. Their correctness, absence of guest reentry and external entry-point binding preconditions remain the integrator's responsibility. Unqualified imports, indirect calls, recursive call chains, unresolved parameter writes and unproved indexed aliases still invalidate pointer-cell proofs. Indexed frame writes have bounded proofs only for single-entry straight-line loops with constant initialization, one positive 64-bit increment and an exactly reachable equality exit before the increment. Calls, extra entries/exits, wrapping counters and dynamic bounds are excluded; these proofs do not reconstruct pointer cells. Fixed-size parameter-relative writes are inferred only for proven pointer origins with constant offsets and propagated through acyclic direct/tail calls. Dynamic extents, indexed parameter writes and unresolved aliases remain conservative. Exact stack pointer cells retain provenance through full-width spills/reloads and equal-origin control-flow joins, including declared incoming stack arguments. General range analysis, nonconstant effect sizes and arbitrary struct-pointer reconstruction remain unimplemented. Scalar stack-byte constants support native null arguments and known effect sizes; these constants do not establish native pointer provenance. Explicit checked stack accesses emit native bounds/alignment guards; object layouts still require recovery evidence, invalid accesses trap rather than deliver guest faults, and instrumentation costs are not game-performance qualified. Arbitrary pointer reconstruction, x87, guest fault delivery, guest TLS, C++ exceptions, aggregates, varargs, atomics, concurrent memory ordering, module closure and lifecycle remain incomplete. Its emitted objects need native import providers. The optional native image registry validates process metadata and allocator callback bindings for one main image; module unloading, dynamic metadata replacement and allocator extension callback ABIs are not supported. The optional immutable-data profile uses native symbolic relocations and startup page-protection checks; guest/provider writes, remapping and rebinding of those regions are outside its contract. The optional source-built hello_notify runtime provides one statically linked main image and its required native providers; it does not provide a complete game runtime or application package. The current macOS guest heap uses the existing host-allocation path rather than a reserved PS5 address arena. Main-image allocation registration reads actual Mach VM page protections; dynamic module registration is not implemented. Linux x86-64 validates and cross-compiles the example without execution. The optional Linux ARM64 validation target emits ELF and executes the source-built example natively; it uses the same lowering and native providers with ELF RELRO instead of Mach-O readonly sections. This validates the tested program path, not all guest instructions or Linux ABI combinations; no full Linux ARM64 game port is provided. The example annotation builder accepts only its pinned sources, known ABI declarations, matched object code and fixed DWARF stack location; it is not general automatic ABI recovery.
- [Guard recipes](../../../core/aot/contract_recipe.py) derive mapping-check sites only under explicitly qualified native-address and ABI policies. Source identities and fact digests detect stale evidence; they do not prove declarations correct. The cube recipe preserves its existing one-byte mapping checks and nullable pointer arguments. Object identity, full access bounds and lifetime remain source obligations. The independent recipe tests cover synthetic load/call inputs, not an unseen full program or general ABI recovery.

- The opt-in [guest-state ordered memory profile](../../../core/aot/guest_emit.py) emits side-effecting AArch64 loads/stores with compiler memory clobbers and full `dmb ish` barriers. This conservatively strengthens x86 store-to-load ordering; it is not a TSO implementation permitting every x86 outcome or a performance optimization. Qualification requires ordinary coherent cacheable memory, naturally aligned scalar conflicting accesses of one width, and race-free provider buffers. Unaligned, mixed-width and vector races, MMIO, non-temporal memory and guest signal delivery are not qualified. Access classification is an integrator obligation, not inferred by `--concurrent`. Wide ordinary transfers are split; no 128-bit atomicity is promised. The glibc bridge adds default joinable pthread create/join, independent static TLS, once and default mutex/condition lifetime. Cancellation, detach, pthread_exit, custom attributes, robust/recursive synchronization and fork are unsupported; missing providers fail at load. Thread creation is refused unless the descriptor declares the ordered memory profile. Native litmus observations and zstd worker tests do not establish universal concurrency correctness.

- [Guest numeric lowering](../../../core/aot/guest_ops.py) widens binary32/binary64 FLD operands to the explicit x87 80-bit encoding, including zeros, subnormals, infinities and quieted signaling NaNs, only with masked x87 exceptions. FNSTCW exposes the retained control word. Per-slot validity rejects stack underflow/overflow instead of synthesizing masked x87 stack faults. CVTTPD2DQ supports the default masked MXCSR profile, truncation, the integer-indefinite result and the legacy 16-byte memory alignment requirement. Floating-point status flags, unmasked exceptions and general x87 arithmetic remain unimplemented; this is not full floating-point-environment support. Semantics follow the Intel SDM FLD, FNSTCW and CVTTPD2DQ entries, with offline Rosetta comparisons and explicit encoding-boundary cases. The jq input which exposed these missing forms is no longer an unseen holdout after this change; a bounded glibc provider bridge now runs its core CLI suite; it remains an adapted consumer, not a fresh holdout.

- [SCE application startup](../../../core/aot/guest_emit.py) is opt-in and distinct from the glibc entry ABI. It accepts position-independent ET_DYN and ET_SCE_DYNEXEC images under the declared argc/argv-in-RDI, optional teardown-in-RSI contract. The adapter supplies no loader teardown callback. Binding SCE imports, process services, the application-supplied libc PRX, module initialization and unload are not implemented by this adapter. Native ABI tests qualify the argument block and stack only. The original independent boilerplate ELF still has unsupported instructions and cannot run through this adapter yet.

- [Guarded ordered accesses](../../../core/aot/guest_emit.py) optionally use LLVM volatile `seq_cst` loads/stores only after checking natural alignment for 8/16/32/64-bit scalar accesses. Unaligned accesses retain full barriers; locked operations retain their own alignment checks. Provider/callback boundaries and CPUID are fenced. The SC lowering follows the AArch64 LDAR/STLR mapping described in the Cambridge C/C++11 mappings (https://www.cl.cam.ac.uk/~pes20/cpp/cpp0xmappings.html). This preserves the conservative qualified profile; it does not justify treating arbitrary guest data as private or permitting mixed-width/vector races. Weaker RCpc and LSE2 variants remain research experiments and are not selected by this option.

- [CLI glibc providers](../../../core/libs/native/NativeAotGlibcMath.cpp) bridge binary64 libm arguments, the explicit x86 extended argument to nexttoward, glibc tm/timeval layouts, environment and basic string/path services. Transcendentals use Darwin libm: arbitrary bit-identical glibc libm results, unmasked exceptions, guest floating-point status and non-C locale equivalence are not established. Historical SVID math modes are excluded. Non-null gettimeofday timezone arguments and unmapped pathconf names fail explicitly. The jq qualification uses the pinned source without Oniguruma; regex support is excluded. Thread-specific keys are process-unique 32-bit IDs with per-thread values and at most four destructor passes before join completes; key deletion does not invoke destructors. Cancellation, explicit pthread_exit and detach remain unsupported.

- [Memory-epoch specialization](../../../core/aot/guest_emit.py) is opt-in for the glibc standalone guest-state profile. A private version runs only until the owning thread crosses a boundary which publishes guest memory: worker creation, shared/file-backed mappings, signal registration, or an unqualified provider. Promotion is monotonic; suspended frames resume ordered AOT code after the completed call without replay. Foreign native threads cannot initiate the first promotion while private guest code is running. This does not infer private buffers inside an already multithreaded program. Provider/runtime internals remain opaque and are outside guest memory. The optional sealed-image profile additionally requires explicit provider mapping-effect qualification and rejects overlapping fixed mappings/unmaps. Only tables on actually readonly pages, with bounded selectors and no relocation overlap, can omit target revalidation; other tables retain the original membership fallback. No generic game or Rosetta speed claim follows. Descriptor version 8 requires regenerated objects.

- [Qualified scalar provider calls](../../../core/aot/guest_provider_calls.py) cover nine allocation/memory/string interfaces. A runtime function-identity check selects the direct native ABI; replacements retain the general provider path. Both adapters call the same implementation. Ordered calls retain fences, calls preserve guest stack writes and read the post-call return address. Sparse writeback is derived from the lowering's register writes, not an assumed C signature. Bulk copies use a checked disjoint region in the private epoch; overlaps retain sequential x86 string semantics. Dense jump-table selectors are hints unless sealed mapping, control and relocation conditions are all verified.
